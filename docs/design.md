# KRX 4분 예측 엔진 설계

- 작성: 2026-10-08
- 상태: 확정 (설계 인터뷰 Q1–Q34 합의)
- 관련 문서: [paid-data.md](paid-data.md) (유료 데이터 조사)

## 1. 목표와 범위

**목표.** KRX 종목의 4분 뒤 가격 움직임을 여러 퀀트 알고리즘이 각자 다른 로직으로 예측하고, 그 예측을 자동 채점해 통계로 보여준다. 결과는 스캘핑할 때 참고 자료로 쓴다. 알고리즘은 매일 스스로 다시 학습한다.

**하지 않는 것.**
- 주문 실행. 엔진에는 주문 코드가 없고, 앞으로도 넣지 않는다.
- 투자 조언. 엔진은 통계 신호만 낸다.

**사용 환경.** macOS(MacBook Pro M4, 16GB)와 Windows. 두 컴퓨터 모두 Fincept Terminal 안의 화면으로 결과를 본다.

## 2. 전체 구조

```
[KIS Open API]
   │ WebSocket(실시간) / REST(조회)
   ▼
[상시 서버: AWS Lightsail 서울 2GB, Docker]
   수집기 ─► 원본 Parquet(하루 단위) ─► S3 (영구 보관)
   피처 저장소 ─► 알고리즘 N개 ─► Condorcet(합의) ─► 채점·통계(SQLite)
   엔진 API(HTTP/WebSocket) ◄─ Tailscale ◄─ Fincept 화면 (Mac, Windows)
   텔레그램 봇 (장애·비용 알림)

[EC2 Spot 학습 서버] 매일 16:00 기동
   S3 데이터 ─► 학습·검증(champion/challenger) ─► ONNX 모델 + 검증 리포트 ─► S3
   상시 서버가 다음 날 08:00에 새 모델로 교체
```

학습하는 곳과 실시간으로 예측하는 곳을 분리한다. 학습은 PyTorch·LightGBM 등으로 하고, 실시간 예측은 ONNX Runtime 같은 가벼운 런타임으로 한다. 그래서 학습 장비를 바꿔도 상시 서버는 영향을 받지 않는다.

## 3. 저장소와 upstream 동기화

| 저장소 | 공개 | 내용 |
|---|---|---|
| `codeyoma/FinceptTerminal` | 공개 (GitHub fork는 비공개로 바꿀 수 없음) | Fincept 화면 코드만. 엔진 주소는 설정 파일에서 읽는다. |
| `codeyoma/krx-quant` | 비공개 | 엔진, 알고리즘, 학습 파이프라인, 문서 |

`krx-quant`는 fork를 `fincept/` submodule(`custom` 브랜치)로 포함한다. 그래서 `krx-quant`를 한 번 clone하면 두 저장소를 모두 받는다. 엔진 API 변경과 그에 맞는 화면 버전은 한 커밋으로 묶는다. 이렇게 하면 엔진과 화면 버전이 어긋나지 않는다. 비공개 저장소의 흔적은 공개 fork에 남지 않는다.

**fork 브랜치.**
- `main`: upstream 미러. 직접 커밋하지 않는다.
- `custom`: 개인 빌드. 기본 브랜치다. upstream은 릴리스 태그(v4.x)만 merge 하고, rebase는 하지 않는다. 맥과 윈도우가 같은 이력을 공유하기 때문이다.
- `custom/UPSTREAM_BASE`에 현재 기반 태그를 적는다 (시작: v4.5.0).
- `custom-upstream-watch` workflow가 매주 월요일 09:00 KST에 `main`을 동기화한다. 새 릴리스가 나오면 issue를 연다.
- 반영은 `custom/merge-upstream-release.sh`로 한다. 자세한 내용은 fork의 `custom/README.md`에 있다.

**Fincept 수정 원칙.**
- 새 화면 하나만 추가한다. 화면 등록 때문에 고치는 upstream 파일은 `fincept-qt/CMakeLists.txt`, `src/app/WindowFrame_Setup.cpp`, `src/app/DockScreenRouter.cpp`, `src/ui/navigation/ToolBar.cpp`, `src/ui/navigation/CommandBar.cpp`로 제한한다.
- Fincept SQLite migration은 쓰지 않는다. upstream의 다음 번호와 충돌하기 때문이다.
- 개인 빌드에서는 앱 내 자동 업데이트를 끈다.
- upstream의 예약·릴리스 workflow는 fork에서 disable 했다.

**기타.**
- 라이선스: AGPL-3.0. 개인 사용이므로 문제없다.
- Fincept 로그인: 무료 계정을 그대로 쓴다. 엔진은 로그인과 무관하게 동작한다.
- 빌드: P3에서 GitHub Actions workflow를 만든다. `custom`에 태그를 달면 맥 DMG와 윈도우 `setup.exe`를 만든다. 코드 서명은 없어서 첫 실행 때 Gatekeeper와 SmartScreen 경고를 한 번 허용해야 한다.

## 4. 데이터

### 4.1 출처

- KIS Open API만 쓴다. 실전계좌를 쓴다. 과거 분봉 조회와 선물 실시간에 실전계좌가 필요하다.
- 엔진에는 주문 기능을 구현하지 않는다. CI가 주문 TR 코드가 코드에 들어오는 것을 막는다.
- 나무증권(NH) API는 쓰지 않는다.

### 4.2 종목

- 삼성전자(005930), SK하이닉스(000660), 삼성전기(009150). 사용자가 추가할 수 있다.
- 실시간 구독 한도는 세션(앱키 하나)당 41건이다(2026-10-08 실측). 종목 하나에 6건이 들고, 시장 전체 피드가 약 20건을 쓴다. 그래서 3종목이면 모든 피드가 실시간으로 들어가고, 종목을 늘리면 뒤쪽 피드부터 REST 조회로 바뀌거나 빠진다. 더 늘리려면 KIS 계좌를 하나 더 만들어 앱키를 2개로 쓴다.

### 4.3 실시간 피드

구독 순서와 키, REST 대체는 [kis-feeds.md](kis-feeds.md)에 정리했다. 요약하면 다음과 같다.
- **WebSocket 38건(3종목 기준)**: KOSPI200 선물, 달러선물, 미국 주간거래 NVDA·MU·AMD, 종목별 통합 체결·통합 호가·프로그램매매·회원사, 업종지수 3개, 등가격 ±2 행사가 옵션 10개, KRX 상장 미국 ETF 2개, 종목별 KRX·NXT 전용 체결.
- **REST**: 외국인·기관 추정 가집계(5분 간격). 한도를 넘어 잘린 체결·호가·회원사·지수는 REST로 5초마다 조회한다.
- 한도가 41건으로 확인되어, 원래 2순위였던 회원사·업종지수·ETF·옵션 IV도 WebSocket으로 받는다.
- 선물과 옵션 코드는 KIS가 매일 배포하는 마스터 파일에서 최근월물을 찾는다. 옵션 전광판 API는 행사가 높은 쪽 100개만 줘서 쓰지 않는다.

### 4.4 과거 데이터

- 1분봉 1년치를 받아 채운다 (`FHKST03010230`, 호출당 120개).
- 호가와 틱 체결은 과거 데이터를 무료로 받을 곳이 없다. 그래서 수집기가 직접 녹화한다. 녹화가 빠진 구간은 복구할 수 없어서 결측으로 표시한다.
- 서버 재시작이나 장애로 빈 구간이 생기면 1분봉은 자동으로 다시 받아 채운다.

### 4.5 매크로 지표

- 공식 출처를 우선 쓴다.
  - 한국은행 ECOS: 금리, 환율
  - FRED: 미국 금리, 유가
  - yfinance: SOX, NVDA, MU, NQ 등 미국 종가
  - KIS: 달러선물, KRX 금
- 공식 출처에 없는 항목만 네이버 시장지표에서 낮은 빈도로 가져온다. 네이버는 robots.txt와 약관상 자동 수집을 허용하지 않는다. 이 위험은 인지하고 선택했다.
- 장중 실시간 피처로는 달러선물을 쓴다. 금리와 원자재는 하루 단위 "국면" 정보로만 쓴다.

### 4.6 유료 데이터

v1에서는 쓰지 않는다. 조사 결과는 [paid-data.md](paid-data.md)에 있다.
- 1순위 후보: KIS 일본 실시간 (도쿄일렉트론, 어드반테스트).
- CME 선물은 보류한다. 알고리즘이 데이터를 쓰면 Non-Display 라이선스($457/월)가 필요할 수 있다.

### 4.7 저장

- 원본 체결·호가: 하루 단위 Parquet 파일로 저장하고, 장 마감 후 S3에 올린다. 영구 보관한다.
- 피처, 예측, 채점, 통계: 상시 서버의 SQLite에 저장한다.
- 백업: Lightsail 스냅샷을 매일 뜬다.

### 4.8 거래 일정

- KIS 휴장일 API와 특수일 목록을 쓴다. 특수일은 연초 첫 거래일과 수능일(10:00 개장)이다.
- 2026-09-14부터 생긴 KRX 애프터마켓(16:00–20:00)과 NXT 단독 시간대는 대상이 아니다.

## 5. 예측 정의

- **시간.** KRX 연속매매 09:00–15:20. 시가·종가 동시호가는 제외한다.
- **주기.** 1분봉이 마감될 때마다 모든 알고리즘이 모든 종목을 예측한다.
- **정답 가격.** 통합 중간가다. KRX와 NXT를 합친 최우선 매수호가와 최우선 매도호가의 평균이다. NXT가 열리기 전인 09:00:00–09:00:30에는 KRX 호가만 쓴다.
- **대상.** 예측 시점 t의 중간가 대비 t+4분 중간가의 변화.
- **출력.** P(상승), P(보합), P(하락), 기대수익(틱).
- **보합 판정.** |변화| < k틱이면 보합이다. k는 왕복 거래비용 이상이 되도록 현재가와 호가단위표로 자동 계산한다.
  - 2026년 거래세는 매도 시 0.20%다.
  - 수수료율은 설정값이다.
- **시간 예산.**
  - 알고리즘 하나는 한 번 예측하는 데 최대 30초까지 쓸 수 있다.
  - 서버 전체 CPU 예산은 따로 둔다. 예산을 넘으면 순위가 낮은 알고리즘부터 그 회차를 건너뛰고 기록한다. 이런 일이 잦으면 서버를 늘리라고 경고한다.
- **합의.**
  - 빠른 합의: 봉 마감 +2초에 낸다. 그때까지 끝난 알고리즘만 쓴다.
  - 최종 합의: 봉 마감 +30초에 낸다.
- **특수 상황.**
  - VI 단일가매매 중에는 예측하지 않는다.
  - 4분 구간 안에 VI, 서킷브레이커, 사이드카가 끼면 그 예측은 "특수"로 따로 채점한다. 기본 통계에서는 뺀다.

## 6. 채점과 통계

**채점 기준 두 가지.** 모든 예측과 합의를 두 기준으로 모두 채점한다.
- (A) 봉 마감 기준: t의 중간가에서 t+4분 중간가까지. 모델 실력을 본다.
- (B) 표시 시점 기준: 신호가 화면에 표시된 시각의 중간가에서 t+4분 중간가까지. 실제로 신호를 따라 매매했을 때의 성적이다. **화면 맨 위에는 (B)를 보여준다.**

**헤드라인 지표.** 95% 신뢰구간을 함께 보여준다.
- 방향 정밀도: 상승·하락이라고 예측한 것 중 맞은 비율. 커버리지(방향을 예측한 비율)와 함께 본다.
- 기준 예측 대비 개선폭(lift). 기준 예측은 "항상 보합", "직전 4분 방향 지속", "클래스 비율대로 무작위" 세 가지다.
- 비용 반영 가상손익(틱).

**상세 지표.**
- 3클래스 정확도
- Brier 점수와 보정도
- 분해: 종목별, 30분 시간대별, 모델 버전별, 기간별(오늘/5일/20일)

**운 보정.** 알고리즘이 많으면 운으로 상위에 오르는 경우가 생긴다. 이를 막기 위해 다음을 적용한다.
- 순위표는 평균이 아니라 신뢰구간 하한으로 정렬한다.
- 최소 표본 수를 채운 알고리즘만 순위에 올린다.
- 기준 예측 대비 개선은 FDR 보정으로 판정한다.
- Condorcet 가중치는 균등 쪽으로 당긴다(shrinkage). 여러 기간에서 꾸준한 알고리즘만 가중치를 올린다.

## 7. 알고리즘

### 7.1 명단 (v1)

"첫날"은 1분봉 1년치로 바로 시작한다는 뜻이다. "수습"은 호가 녹화가 10거래일 쌓일 때까지 순위표와 합의에서 빠진다는 뜻이다.

| 이름 | 성격 | 핵심 로직 | 주요 피처 (**굵게** = 고유 피처) | 매일 학습하는 것 | 시작 |
|---|---|---|---|---|---|
| Newton | 추세 추종 | 가격의 속도와 가속도에 거래량을 '질량'으로 곱해 '힘'을 구한다. 마찰(감쇠)을 넣어 4분 뒤를 외삽한다. | **수익률 기울기와 2차 미분, 거래량 가중** | 감쇠율, 임계값 | 첫날 |
| Gauss | 역추세 | 당일 VWAP 대비 z-score를 구하고, Ornstein–Uhlenbeck 평균회귀 속도로 되돌림 확률을 낸다. | **VWAP 대비 z-score, 평균회귀 속도**, 실현변동성 | OU 파라미터, z 임계값 | 첫날 |
| Kalman | 잡음 제거, 선물 추종 | 상태공간 모델로 microprice에서 숨은 적정가와 추세를 추정한다. KOSPI200 선물을 외부 입력으로 쓴다. | **선물을 입력으로 받는 필터**, microprice, 베이시스 | EM으로 잡음 공분산 추정 | 수습 |
| Shannon | 호가창 해독 | 주문흐름 불균형(OFI), 잔량 불균형, 체결방향 엔트로피로 다항 로지스틱 회귀를 한다. | **OFI, 체결방향 엔트로피**, 10단계 호가, KRX/NXT 체결 비중, 프로그램매매, 회원사 흐름 | L1 로지스틱 재학습 | 수습 |
| Poisson | 쏠림 감지 | 매수·매도 시장가 체결의 도착을 Hawkes 과정(자기흥분 점과정)으로 모델링한다. 어느 쪽 쏠림이 강한지 본다. | **체결 도착 시각·방향·크기만** | 최대우도로 강도 파라미터 추정 | 수습 |
| Markov | 국면 탐정 | 4국면(조용함/상승추세/하락추세/급변동) 은닉 마르코프 모델을 쓴다. 다음 국면 전이확률을 예측으로 바꾼다. | **매크로 일일 국면별 전이행렬**, 옵션 IV 국면, 변동성, 스프레드, 시간대 | Baum–Welch 재추정 | 첫날 |
| Granger | 이웃 관찰 | Granger 인과 검정으로 선행-후행 관계를 찾아 회귀한다. 이웃 종목과 시장 지표가 먼저 움직인 것을 반영한다. | **3종목 간 시차, 달러선물, 업종지수, 미국 주간거래 MU·NVDA, KRX 상장 미국 ETF** | 시차와 계수 재선택 | 첫날 (선물 과거 분봉을 받을 수 있을 때. 아니면 수습) |
| Turing | 만능 학습 | LightGBM으로 상승/보합/하락을 분류한다. | 전체 피처 + **시간대, 옵션 만기일, 투자자별·프로그램매매·회원사 흐름** | 최근 60거래일 롤링 재학습 | 첫날은 1분봉 버전, 10거래일 뒤 호가 피처 추가 |
| Condorcet (메타) | 합의 | 각 알고리즘의 확률을 최근 성적(종목·시간대별 로그손실)으로 가중해 합친다. 수습·벤치·복제 상태는 뺀다. | 각 알고리즘 출력과 최근 성적 | 가중치 재계산 | 첫날 |

- 예비 후보: Mandelbrot. Hurst 지수로 추세 지속과 되돌림을 판정해 둘 사이를 전환한다. Markov와 역할이 겹쳐 v1에서는 뺐다.
- 알고리즘끼리는 서로의 출력을 보지 않는다. 출력을 합치는 것은 Condorcet뿐이다.

### 7.2 알고리즘 모듈 규약

- 위치: `algorithms/<name>/`
- 각 모듈은 공통 인터페이스를 따른다. 사용하는 피처 선언, `fit`, `predict`, 모델 버전.
- 각 모듈에는 **성격 카드**를 둔다. 과학자, 핵심 로직, 고유 피처, 학습 방법을 적는다.
- 피처는 공용 피처 저장소가 1분에 한 번만 계산한다. 알고리즘은 그 결과를 공유한다.

### 7.3 개성 검사

- 등록할 때: 피처 조합이 기존 알고리즘과 같거나 고유 피처가 하나도 없으면 거부한다.
- 수습 중: 기존 알고리즘과의 예측 상관이 0.9를 넘으면 "복제"로 표시하고 합의에서 뺀다.

### 7.4 새 알고리즘 추가 절차

1. 모듈과 성격 카드를 작성한다.
2. 재생 테스트를 통과시킨다. 저장된 최근 20거래일 데이터로 돌려서 실시간과 같은 채점·통계를 낸다. 시간 예산과 개성 검사도 이때 확인한다.
3. 수습으로 시작한다. 공식 성적은 실시간 결과만 인정한다.

### 7.5 상태 관리

| 상태 | 합의 참여 | 진입 조건 |
|---|---|---|
| 수습 | X | 새로 등록됨 |
| 정식 | O | 수습 10거래일 후, 기준 대비 lift의 신뢰구간 하한 > 0 (자동) |
| 벤치 | X (예측·채점은 계속) | 정식 중 최근 20거래일 lift ≤ 0 (자동) |
| 은퇴 | X (예측 중단, 기록 보존) | 벤치 60거래일 동안 회복 없음 → 은퇴 후보 → 사용자 승인 |

## 8. 학습

- 매일 16:00 KST에 EventBridge Scheduler가 EC2 Spot 인스턴스를 띄운다. 기본은 CPU 인스턴스이고, 신경망 알고리즘이 있을 때만 GPU 인스턴스를 쓴다.
- 각 알고리즘은 롤링 구간 데이터로 walk-forward 학습을 한다. 기본 구간은 20거래일이고 Turing은 60거래일이다.
- 새 모델(challenger)이 학습에 쓰지 않은 최근 며칠에서 현재 모델(champion)보다 나을 때만 교체한다.
- 결과 모델(ONNX)과 검증 리포트를 S3에 올리고 인스턴스는 스스로 종료한다.
- 상시 서버는 다음 날 08:00에 새 모델로 교체한다.
- 07:30까지 학습이 끝나지 않으면 기존 모델을 그대로 쓴다.
- Spot 인스턴스가 중간에 회수되면 체크포인트부터 다시 시작한다.
- 모델 버전 이력을 남기고 롤백할 수 있다. 모든 예측에는 모델 버전을 기록한다.

## 9. 인프라와 비용

- **상시 서버.** Lightsail 서울 2GB, 월 $12. IPv4 주소가 있는 요금제여야 한다. KIS 서버에 IPv6 주소가 없기 때문이다. 엔진은 Docker로 띄운다.
  - Lightsail은 버스트형 CPU다. 부하가 늘면 4GB($24) 요금제나 비버스트형 EC2로 옮긴다.
- **접속.** Tailscale(무료)로 상시 서버, 맥, 윈도우를 연결한다. 서버 포트는 인터넷에 열지 않는다.
- **비밀값.** API 키 등은 서버의 `.env` 파일(권한 600)에만 둔다. 저장소에는 커밋하지 않는다.
- **비용 상한: 월 $100.**
  - AWS Budgets로 $50과 $80에 텔레그램 알림을 보낸다.
  - $100에 도달하면 그달 남은 기간은 Spot 학습을 멈춘다. 실시간 예측은 계속한다.
  - 예상 비용: 서버 $12, S3 $1 미만, Spot 학습 $3–15(미확인).
- **장애 알림.** 텔레그램 봇으로 보낸다. 대상은 KIS 연결 끊김, 데이터 지연, 학습 실패, 비용 경고다.

## 10. Fincept 화면

- **구성.** 종목별로 다음을 보여준다.
  - 1분봉 차트에 합의 예측 화살표와 채점 결과(✓/✗)를 겹쳐 표시
  - 알고리즘별 예측 패널: 상승/보합/하락 확률, 기대수익(틱), 빠른·최종 합의, 채점까지 남은 시간
  - 순위표: 오늘/5일/20일 성적과 모델 버전, 상태
  - 매크로 줄: 달러선물, 오늘의 시장 국면
  - 엔진 상태: KIS 연결, 데이터 지연, 어젯밤 학습 결과(교체 여부)
- **신호 알림.** Condorcet 확률이 기준값 이상이고 N개 이상의 알고리즘이 같은 방향이면 데스크톱 알림과 소리를 낸다. 기준값과 N은 화면에서 조정한다. 텔레그램 신호 알림은 옵션이다.
- **언어.** 한국어. 알고리즘 이름은 영어로 쓴다.
